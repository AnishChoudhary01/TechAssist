Exercise 3 · how each metric is calculated

Quality

  • Correctness / Accuracy — 100 × (gold expected_terms found in the answer) / |expected_terms|, then averaged over 24 questions.
  • Relevance — mean of expected-term coverage and question-token coverage of the answer.
  • Retrieval Quality — 100 × (retrieval_terms found in the frozen top-4 RAG context) / |retrieval_terms|. Same context for every model.
  • Hallucination Rate — unsupported commands (chkdsk, sfc, msconfig, diskpart, regedit, wget, curl) in the answer but not in context, divided by sentence count. Lower is better.
  • Test-Pass Rate — executable check of is_valid_port on 1, 65535, 0, 65536, "80", and True. Non-code questions are excluded.

Performance

  • Response Latency — wall-clock ms around Ollama /api/generate, averaged per model (temperature 0.2, seed 42, 256 tokens).
  • Token Usage — Ollama prompt_eval_count / eval_count, shown as mean prompt / mean completion tokens.
  • CPU / Memory / GPU — CPU is Δ Ollama process CPU seconds / wall time when visible; memory is Ollama /api/ps loaded size; GPU is size_vram (0 on CPU-only hosts).
